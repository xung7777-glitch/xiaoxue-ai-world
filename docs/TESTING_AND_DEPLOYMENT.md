# 測試與部署規則

## 登入及雲端功能

Google 登入／登出、OAuth 回呼、身分驗證、資料庫讀寫、Netlify Functions，以及任何依賴正式 HTTPS 網域或雲端服務的功能，必須在部署後的外部網站測試。

- Codex 內建瀏覽器只可用於查看畫面或初步檢查，不作為登入、OAuth 或資料庫功能的驗收依據。
- 完成相關程式及設定後，先部署到可由外部瀏覽器存取的網站，再請使用者用外部 Chrome 或手機測試。
- 回報測試時提供實際部署網址、部署結果及需要操作的步驟。只有使用者在外部網站完成操作後，才記錄為使用者驗收通過。
- 登入與雲端功能的部署測試應集中在相關修改完成後進行，避免每個小改動都部署一次。

## 一般介面修改

文字、顏色、排版、圖片位置等不依賴登入或雲端服務的修改，可先在本機預覽及檢查，不需要為了每次檢查而部署。當使用者需要在正式網站查看或確認時，再安排部署。

## 回報與紀錄

- 明確區分本機檢查、部署成功、外部網站測試及使用者驗收；不得把其中一項描述成另一項。
- 外部登入測試失敗時，先記錄實際瀏覽器、網址及錯誤訊息；不要只憑 Codex 內建瀏覽器的結果判定身份服務故障，也不要未驗證就更換登入供應商。
- 每次修改依 `CHANGELOG.md` 規則記錄執行者、修改內容、驗證結果、部署狀態及待辦事項。
